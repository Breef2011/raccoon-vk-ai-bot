## English summary

A production-shaped VK community chatbot powered by the GigaChat LLM. It receives messages through the VK Long Poll API, grounds answers in a local Markdown knowledge base, keeps per-user dialog memory and hands over to a manager when the knowledge base has no answer. The project ships with configuration validation, retry/backoff for flaky LLM responses, offline unit tests and a GitHub Actions pipeline.

## Задача

Сообщество «Еноты» во ВКонтакте получает десятки однотипных вопросов: чем кормить енота, где он живёт, опасно ли держать его дома, как он зимует. Отвечать вручную долго, а универсальная языковая модель без ограничений начинает выдумывать факты и уходить в посторонние темы.

Нужен был бот, который:

1. отвечает от лица сообщества в привычном для пользователя чате ВКонтакте;
2. держится фактов о еноте-полоскуне и не фантазирует;
3. помнит контекст разговора, но не хранит данные бесконечно;
4. аккуратно передаёт человеку вопросы, на которые нет точного ответа;
5. не падает при сбоях внешних API и не светит секреты в логах.

## Решение

Бот **«Енот Валера»** построен как тонкий слой между VK API и GigaChat API:

- **VK Long Poll** доставляет входящие сообщения сообщества, ответы уходят через `messages.send`;
- **системный промпт** задаёт роль, стиль и границы темы, а также запрещает выдумывать факты;
- **локальная база знаний** в Markdown подставляется в промпт — модель отвечает не «из головы», а по проверенному тексту;
- **GigaChat** генерирует ответ с учётом истории диалога пользователя;
- если точного ответа нет или вопрос коммерческий — бот предлагает форму связи с менеджером.

Проект оформлен как самостоятельное приложение: конфигурация через `.env` с валидацией, диагностика доступов, офлайн-тесты и CI.

## Возможности

| Возможность | Детали реализации |
|---|---|
| Приём сообщений | VK Long Poll API (`VkBotLongPoll`), событие `message_new` |
| Резервный транспорт | Если события Long Poll в сообществе недоступны, бот автоматически переходит на опрос `messages.getConversations` + `messages.getHistory` (`VK_TRANSPORT=auto`) |
| Генерация ответов | GigaChat API: OAuth-токен + `POST /v1/chat/completions` |
| Работа с токеном | Access token кэшируется, обновляется по `expires_at` и принудительно — при `401` |
| Знания | Локальная база `knowledge/raccoon_knowledge.md`; пока база укладывается в лимит — уходит целиком, иначе выбираются релевантные разделы |
| Роль и стиль | Отдельный файл `prompts/system_prompt.txt` с плейсхолдерами `{{KNOWLEDGE_BASE}}` и `{{CONTACT_FORM}}` |
| Память диалога | История на каждого пользователя, ограничение длины (`MAX_HISTORY_MESSAGES`) и времени жизни (`DIALOG_TTL_MINUTES`) |
| Команды | `/start`, `помощь`, `сброс`, `контакты` (и их англоязычные алиасы) |
| UX в чате | Индикатор «печатает…», обработка длинных ответов частями, защита от повторной обработки сообщений |
| Надёжность | Повторы с экспоненциальной задержкой при `429`/`5xx`, понятное сообщение пользователю при отказе модели |
| Диагностика | `python main.py --check` проверяет токены, доступ к моделям и сообществу, не отправляя сообщений |
| Приватность | Тексты сообщений не пишутся в логи, секреты живут только в `.env` |
| Тесты | 27 офлайн-тестов (`unittest`) без обращения к реальным API |
| CI | GitHub Actions: тесты на Python 3.10–3.13 |

Linux / macOS:

```bash
git clone https://github.com/Breef2011/raccoon-vk-ai-bot.git
cd raccoon-vk-ai-bot
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
nano .env
```

### 2. Заполнить `.env`

Обязательны только `VK_GROUP_TOKEN` и `GIGACHAT_CREDENTIALS`. Полное описание — в разделе [Переменные окружения](#переменные-окружения).

```dotenv
VK_GROUP_TOKEN=<токен сообщества>
GIGACHAT_CREDENTIALS=<authorization key из GigaChat Studio>
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-2
GIGACHAT_CA_BUNDLE=certs/ca_bundle.pem
CONTACT_FORM_URL=<ссылка на форму для связи>
```

### 3. Проверить доступы

```bash
python main.py --check
```

Команда получает токен GigaChat, запрашивает список моделей и проверяет доступ к сообществу. Сообщения не отправляются, секреты не выводятся.

Пример успешного вывода:

```text
Проверяю GigaChat...
  GigaChat: OK. Доступные модели: GigaChat-2, GigaChat-2-Lite, GigaChat-2-Pro
Проверяю ВКонтакте...
  ВКонтакте: OK. Сообщество «Еноты», id=123456789.

Все проверки пройдены. Можно запускать бота без флага --check.
```

### 4. Запустить бота

```bash
python main.py
```

Остановка — `Ctrl+C`.

### 5. Запустить тесты

```bash
python -m unittest discover -s tests -v
```

### Где взять доступы

**GigaChat API** — <https://developers.sber.ru/>: создайте приложение, выберите scope и скопируйте **Authorization Key** (это уже готовая строка Base64 `Client ID:Client Secret`, а не отдельный Client Secret).

**ВКонтакте** — «Управление → Настройки → Работа с API»: создайте ключ с правом «Сообщения сообщества», включите сообщения и Long Poll API с событием «Входящие сообщения».

## Как работает бот

1. `main.py` загружает `.env`, проверяет обязательные переменные, читает базу знаний и системный промпт.
2. `VkBot` подключается к Long Poll API сообщества и слушает входящие сообщения; при недоступности событий переключается на опрос диалогов.
3. Для каждого пользователя `DialogStore` держит отдельную историю (чётное число последних сообщений, TTL, потокобезопасный доступ).
4. `DialogService` собирает запрос: системный промпт + релевантная часть базы знаний + история + новый вопрос.
5. `GigaChatClient` получает access token, кэширует его и вызывает `POST /v1/chat/completions`; при `401` обновляет токен, при `429`/`5xx` повторяет запрос с задержкой.
6. Ответ отправляется пользователю; длинные ответы делятся на части по границам абзацев и предложений (до 3 500 символов).
7. Если модель недоступна после повторов, пользователь получает вежливое сообщение с предложением написать менеджеру.

| Команда | Действие |
|---|---|
| `/start`, `start`, `привет` | Приветствие и краткая инструкция |
| `помощь`, `/help` | Справка по возможностям |

## База знаний и системный промпт

### Системный промпт

`prompts/system_prompt.txt` задаёт:

- роль и характер Енота Валеры, мужской род и доброжелательный стиль;
- границы темы и мягкий возврат к енотам;
- запрет на выдумывание фактов;
- правило предлагать менеджера, если точного ответа нет;
- формат ответов для ВКонтакте.

Плейсхолдер `{{KNOWLEDGE_BASE}}` обязателен: без него бот не запустится и сообщит об ошибке. `{{CONTACT_FORM}}` заменяется на ссылку из настроек или на безопасную инструкцию.

### База знаний

`knowledge/raccoon_knowledge.md` — структурированный Markdown с разделами `##`, подготовленный по статье «Енот-полоскун» в русской Википедии.

- Пока база укладывается в лимит (≈20 000 символов), модель получает её целиком — ответы максимально точные.
- Когда база растёт, `KnowledgeBase` выбирает разделы по ключевым словам запроса, всегда добавляя «Кратко о виде» и «Границы базы знаний».
- Обновление знаний — правка Markdown и перезапуск бота.

## Надёжность и обработка ошибок

| Сценарий | Поведение |
|---|---|
| Истёк access token (`401`) | Токен обновляется и запрос повторяется один раз |
| Лимит запросов или сбой сервера (`429`, `5xx`) | До трёх попыток с экспоненциальной задержкой и джиттером |
| Сетевая ошибка | Повторы, затем понятное сообщение пользователю |
| Модель вернула пустой ответ | `GigaChatError`, пользователь получает fallback-сообщение |
| VK не поддерживает Long Poll | Автоматический переход на опрос диалогов |
| Дубли событий | Дедупликация по `(peer_id, message_id)`, окно на 2 000 сообщений |
| Долгий ответ модели | Параллельная обработка в пуле потоков, по одному активному диалогу на пользователя |
| Остановка | `Ctrl+C`: корректное завершение пула потоков и закрытие HTTP-сессий |

## Безопасность

- Реальные ключи хранятся только в `.env`; файл в `.gitignore`, в репозитории — `.env.example` без значений.
- В коде, тестах и документации нет токенов и паролей.
- Access token GigaChat не попадает в логи и сообщения.
- Тексты сообщений пользователей не логируются: для диагностики используются ID и коды ошибок.
- Для TLS используется цепочка доверия из `certs/` (сертификаты Минцифры + `certifi`), отключение проверки — только для локальной диагностики.
- При компрометации токена ВКонтакте ключ отзывается в настройках сообщества, ключ GigaChat пересоздаётся в Studio.

## Тесты и CI

Тесты полностью офлайн: HTTP-сессии и VK API подменяются фейками, реальные ключи не нужны.

```bash
python -m unittest discover -s tests -v
```

Покрыто:

- парсинг базы знаний и выбор релевантных разделов;
- разбиение длинных сообщений;
- дедупликация и обработка новых сообщений в режиме опроса;
- обрезка истории, сброс и истечение диалога;
- сборка промпта, контакты с URL и без;
- валидация конфигурации и значений по умолчанию;
- кэширование и обновление токена GigaChat, повторы при `5xx`, разбор обёрнутого ответа.

GitHub Actions (`.github/workflows/ci.yml`) запускает тесты на каждый push и pull request в ветки `main` и `develop` на Python 3.10, 3.11, 3.12 и 3.13.

## Ветки и версии

| Ветка | Назначение |
|---|---|

| `feature/*` | Отдельные задачи; вливаются в `develop` через pull request |

Правила:

- коммиты в `main` — только через merge из `develop`;

## Ограничения и планы развития

Ограничения текущей версии:

- история диалогов хранится в памяти процесса и теряется при перезапуске;
- обрабатываются только текстовые сообщения;
- один экземпляр бота рассчитан на одно сообщество;
- бот не заменяет ветеринара и не даёт медицинских назначений.

Планы:

- постоянное хранилище истории (SQLite/Redis) и статистика обращений;
- поддержка вложений: фото, документы, голосовые сообщения;
- вебхуки ВКонтакте вместо Long Poll для масштабирования;
- админ-панель для правки базы знаний без перезапуска;
- Docker-образ и деплой на VPS;
- метрики и трассировка запросов к модели.
